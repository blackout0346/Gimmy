# Gimmy

Gimmy — микросервисная платформа для онлайн-торговли. Проект объединяет работу с пользователями, каталогом товаров, корзиной, личными сообщениями и уведомлениями в единой серверной экосистеме.

Основная цель Gimmy — предоставить масштабируемую основу для маркетплейса, в котором отдельные компоненты можно развивать и развёртывать независимо.


## Что умеет платформа

- регистрация и аутентификация пользователей;
- авторизация запросов с помощью JWT;
- управление профилем и аватаром;
- создание и просмотр каталога товаров;
- работа с категориями, тегами и подкатегориями;
- отзывы и рейтинги товаров;
- управление корзиной;
- личные сообщения между пользователями в реальном времени;
- передача файлов во вложениях сообщений;
- мгновенные уведомления через SignalR;
- кэширование данных и асинхронное взаимодействие сервисов.

## Архитектурный подход

Gimmy использует микросервисную архитектуру на базе .NET и ASP.NET Core. Каждый сервис отвечает за конкретную предметную область, хранит собственные данные и взаимодействует с другими компонентами через HTTP API либо события в RabbitMQ.

Для сценариев, где клиент должен получать обновления без перезагрузки страницы, применён SignalR. Это используется в мессенджере и системе уведомлений.

### Принципы взаимодействия

- Синхронные операции выполняются через HTTP API.
- Асинхронные события передаются через RabbitMQ с использованием MassTransit.
- Для обмена данными в реальном времени используется SignalR.
- Redis применяется для кэширования и снижения нагрузки на основные базы данных.
- PostgreSQL используется как основное постоянное хранилище данных.

## Сервисы

| Сервис | Назначение | Основные возможности |
| --- | --- | --- |
| `AuthService` | Аутентификация и безопасность | Регистрация, вход, хэширование паролей, выпуск и проверка JWT-токенов |
| `UserService` | Пользовательские данные | Профили, изменение данных пользователя, загрузка и выдача аватаров |
| `ProductService` | Каталог товаров | Товары, категории, теги, подкатегории, отзывы, рейтинги и изображения |
| `CartService` | Корзина покупателя | Добавление, изменение количества и удаление товаров из корзины |
| `MessengerService` | Личные сообщения | Чаты, доставка сообщений в реальном времени, отправка и скачивание вложений |
| `NotificationService` | Уведомления | Мгновенная доставка уведомлений подключённым клиентам |

## Безопасность

Для защиты API используются следующие механизмы:

- JWT Bearer Authentication;
- контроль срока действия токенов;
- настройка `ClockSkew = Zero`;
- ограничение частоты запросов (`SlidingWindowLimiter`);
- CORS для разрешённых клиентских приложений;
- хэширование паролей;
- изоляция конфигурации и секретов в переменных окружения.

Не добавляйте реальные пароли, JWT-ключи, адреса серверов или другие секреты в Git-репозиторий.

## Конфигурация

Перед запуском создайте файл `.env` в корне проекта. Он должен содержать параметры PostgreSQL, Redis, RabbitMQ и JWT.

Пример конфигурации:

```env
# PostgreSQL
DB_USER=postgres
DB_PASSWORD=your_postgres_password
DB_NAME=HomeSellerDB
DB_PORT=5432

# Основная и локальная базы данных
ConnectionStrings__NpgsqlConnectionVPS=Host=your_vps_ip;Port=5432;Database=HomeSellerDB;Username=postgres;Password=your_postgres_password
ConnectionStrings__NpgsqlConnectionLocal=Host=localhost;Port=5432;Database=HomeSellerDB;Username=postgres;Password=your_postgres_password

# Redis
Redis__Host=localhost
Redis__Port=6379
Redis__Password=your_redis_password

# RabbitMQ
RabbitMQ__HostName=localhost
RabbitMQ__Username=guest
RabbitMQ__Password=guest

# JWT
Jwt__Issuer=Gimmy
Jwt__Audience=GimmyClient
Jwt__Key=your_super_secret_jwt_key_at_least_32_characters
```

## Подготовка окружения

Для разработки потребуются:

- .NET 10 SDK;
- PostgreSQL;
- Redis;
- RabbitMQ;
- Docker и Docker Compose — для контейнеризированного запуска инфраструктуры;
- файл `.env` с параметрами подключения.

После запуска зависимостей каждый сервис можно запускать из своей директории стандартной командой .NET:

```bash
dotnet restore
dotnet run
```

> Перед запуском убедитесь, что значения строк подключения и параметры RabbitMQ в `.env` соответствуют вашему окружению.

## Работа с базой данных

При запуске сервисы применяют актуальные миграции Entity Framework Core автоматически. Это упрощает первый запуск проекта и синхронизацию структуры базы данных между окружениями.

В `ProductService` предусмотрено начальное заполнение каталога данными из `initData.json`. Оно может включать товары, категории, теги, изображения и отзывы.

## Отказоустойчивость базы данных

Сервисы поддерживают сценарий переключения между удалённым и локальным подключением к PostgreSQL:

1. При запуске проверяется доступность удалённой базы данных.
2. Если подключение к удалённой базе невозможно, используется локальное подключение.
3. Параметры обоих подключений задаются в `.env`.

Это помогает запускать проект локально и снижает зависимость разработки от доступности удаленной инфраструктуры.
